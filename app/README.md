# cbmail

Переписанная почтовая рассылка: FastAPI + SQLAlchemy 2.0, без Django.

## Статус

Готово и покрыто тестами — **ядро системы**. Веб-слой, шаблоны и админка
в работе. Честная разбивка ниже.

```bash
cd app
python -m venv .venv && .venv/Scripts/pip install -e ".[dev]"
.venv/Scripts/pytest              # 153 теста
.venv/Scripts/pytest -m regression # 33 теста на дефекты старой версии
```

## Архитектура

```
cbmail/
  core/      конфигурация, безопасность, лицензирование
  domain/    чистая логика без БД и фреймворка — вся покрыта тестами
  db/        ORM-модели и сессии
  services/  оркестрация: транзакции, блокировки, идемпотентность
  smtp/      отправка почты
  web/       FastAPI: роутеры, шаблоны, зависимости
  workers/   фоновые задачи
```

Правило зависимостей: `domain` не знает ни о чём; `services` знают о `domain`
и `db`; `web` и `workers` знают о `services`. Обратных зависимостей нет —
поэтому логику можно тестировать без поднятия ни базы, ни SMTP, ни HTTP.

## Ключевые решения

**Схема БД не меняется.** Модели описывают таблицы, созданные Django-миграциями.
Переход не требует конвертации данных, откат — запуск прежнего контейнера.
Единственная новая таблица — `cbmail_session`.

**Пароли читаются как есть.** Формат `pbkdf2_sha256$...` — стандартный PBKDF2 из
`hashlib`, не технология Django. Существующие пользователи входят своими паролями.

**Тесты не требуют внешних сервисов.** SQLite в памяти + заглушка SMTP. Полный
прогон — 3 секунды, поэтому тесты реально гоняют, а не пропускают.

**Никаких сигналов.** Вся логика вызывается явно. Отправка письма из
`post_save` была источником самых дорогих дефектов: письма без вложений,
поглощённые ошибки, отправка внутри HTTP-запроса.
